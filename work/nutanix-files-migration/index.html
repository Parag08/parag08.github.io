Mission

The problem

Customers wanted to move their file shares, over SMB and NFS, onto Nutanix Files using Nutanix Move. They needed one place to plan, watch and control a file migration.

The feature had been blocked for two years. It sat between two teams, Move and Files, and nobody clearly owned it. There was no architecture, and the decisions that would let either team start had never been made.

Boss fights

The hardest parts

No ownerBoss 1

Two teams each had a stake, but neither owned the outcome. Nothing could move until someone made the calls.

Key decision

Drawing the line between teams

Control plane

Move (my team)

  • Takes the user’s inputs
  • Discovers shares and builds the migration plan
  • Shows the whole migration in the UI
  • Gives the user control: start, pause, cut over
Files
APIs
Data plane

Nutanix Files

  • Owns the data path
  • Decides how the copy happens
  • Runs the full copy, then delta syncs
  • Exposes the APIs Move calls

Move decides what happens and shows it to the user. Files decides how the data moves. They meet at one interface. That single decision ended two years of ambiguity.

Upgrades picked

What I did

  • DecisionTook ownership and made the calls

    Set the architecture and the framework for how the project would run.

  • DecisionDrew the line between teams

    Move owns orchestration and the user experience; Files owns the data path.

  • ProcessLocked the design early

    Finalised the experience with the UX/UI team before the build scaled up.

  • ProcessSplit the release into six phases

    Each with a predictable timeline. Not usual for the team, but a project this size needed it.

  • DeliveryTracked three teams on one plan

    Every phase had a clear owner and date for Move, Files and UX/UI work running in parallel.

  • DeliveryCleared the bug wall

    Debugged ~300 bugs, routed each to its owner, and resolved them by fixing the design or setting a clear product boundary.
